间隙 · 会议助手（独立侧边应用）
版本：0.3.0；更新：2026-10-22；目标展示：2026-10-23（周五）中午。

这是什么
与腾讯会议并排打开的本机网页助手。腾讯会议负责真人音视频沟通，助手负责分析已经输入的发言、
整理当前请求与背景、准备可编辑回复。它尚未嵌入腾讯会议，也没有读写腾讯会议聊天区的接口。
原来的 prototype/ 是独立保留的历史离线演示。本目录是新的实现。

启动
需要 Node.js 22 或更高版本，无需 npm install。
推荐双击上一级目录“打开会议助手.cmd”，或本目录 start.cmd。
它会自动启动后台服务，确认页面服务就绪后再打开主页面；不需要先在网页里按按钮。
重复双击只打开已有服务，不清空会话。启动窗口自动关闭后，后台服务仍会运行。
“打开录屏工具.cmd”或本目录 record.cmd 也会先保证服务启动，再打开录屏页。
在本目录打开 PowerShell，运行：
    .\start.ps1
仅启动服务、不打开浏览器：
    .\start.ps1 -NoBrowser
需要查看前台输出时可以运行（关闭这个终端会停止该次前台服务）：
    .\start.ps1 -Foreground
也可前台直接运行：
    node server.mjs
默认主页面：
    http://127.0.0.1:8765
录屏工具页面：
    http://127.0.0.1:8765/recorder.html
如果改过 .env 的 PORT，启动入口会自动打开实际端口。
启动脚本在系统没有 Node 时，会尝试本机 Codex 附带的 Node。
彻底关闭后台服务时先导出需要的会议日志，再双击“退出会议助手.cmd”或本目录 stop.cmd。
按提示输入Y确认；这会结束后台进程，页面随后无法连接，再次双击启动入口即可恢复。
日常暂停请使用网页上的“停止会话”，不用退出后台服务。
当前只允许同一电脑访问，不提供局域网或公网连接；开机后需要再次双击启动，不安装开机自启。
若出现ERR_CONNECTION_REFUSED，说明浏览器没有连接到本机服务，请双击上述启动入口。
启动失败会留下提示，日志在 logs/；端口被其他程序占用时不会自动关闭其他程序。

开始、停止与继续会话
打开页面时默认“会话未开始”、00:00，不因服务启动自动开始计时。
点击“开始会话”后才能加入文字、播放剧本、启动转写或分析；这些功能仍由你分别开启。
点击“停止会话”会停止累计计时、麦克风/会议音频采集、剧本回放和自动分析。
正在等待的分析会被取消，旧转写和旧分析结果不再加入本次会话。
停止保留已收到的发言、提醒和草稿，仍可核对、编辑、导出和填写使用反馈。
“继续会话”继续原记录与累计时间，不计算停止期间；不会自动重开麦克风、回放或自动分析。
“新会话”经确认后清空本次记录，保留角色，回到未开始和00:00。反馈文件不会被清空。
会话开关控制的是助手工作状态，本机服务继续运行，方便再次开启；彻底退出后台服务使用stop.cmd。
服务重启仍会丢失内存中的会话记录，需要保存时先导出。反馈是独立持久保存的。

录制演示
顶部“录制演示”在新标签页打开本机录屏工具，也可打开 http://127.0.0.1:8765/recorder.html。
用桌面浏览器点击“开始录制”，按浏览器提示选屏幕/窗口；权限选择需要本人完成。
录制腾讯会议和助手两个窗口时选择整个屏幕，按需勾选系统音频及本页麦克风选项。
先录10秒，回放确认远端和本人声音，再正式录制；浏览器返回音轨不保证里面有声音。
结束后点“停止录制”，等待末段数据收齐，再回放检查并点“保存WebM”。
文件只下载到本机，不自动上传。录屏标签页刷新/关闭会丢失尚未下载的视频。
会话停止和录屏停止是两个按钮：可以先停止会话，再录结尾讲解，最后停止录像。
这只是录屏工具；多人发言、实际发送和主持人回应仍按rehearsal/中的剧本进行。

填写 DeepSeek API Key
1. 用文本编辑器打开本目录 .env。
2. 把 DEEPSEEK_API_KEY= 后面留空的位置替换成你的完整 Key。例如：
       DEEPSEEK_API_KEY=你自己的完整密钥
   不要保留上面的中文示例；不要把真实 Key 贴进聊天、截图、public/ 或提交包。
3. 默认服务地址和模型为：
       DEEPSEEK_BASE_URL=https://api.deepseek.com
       DEEPSEEK_MODEL=deepseek-flash
4. 保存后先用stop.cmd退出服务，再用start.cmd重新启动。只重复双击启动不会重启已有服务。
   网页只显示配置状态，不显示密钥。
5. 输入一条不敏感的测试发言并点击分析，才会实际调用服务、产生按账户规则计费的请求。

.env.example 是可分享的空模板；.env 已列入 .gitignore。
.gitignore 不会阻止人工打包，请分享项目时主动排除 .env。
2026-10-22已用真实Key完成一次虚构排练发言的分析：官方接口200，提醒、原话引用和草稿通过结构校验。
这次分析约1.7秒，只代表该次文字输入调用。随后已有本机麦克风及系统混合音频的实际发言进入分析，用户确认腾讯会议声音能够接收；指定应用隔离和多人完整收发流程仍需实测。
可手动运行 node scripts/check-deepseek.mjs 复查；它会产生一次真实API请求，使用独立虚构会话，
不改变网页当前会议，结果写入 test-output/live-deepseek-latest.json，不记录密钥。
该脚本不包含在自动测试中。未配置时显示错误，不用预设回答冒充模型结果。

分析按钮与自动模式
演示流程：开始/继续会话 → 填写称呼与职责 → 开启“自动分析新发言” → 开启语音转写或加入文字。
自动模式只需开启一次；后续已加入记录的新发言会自动分析，不需要每次点击按钮。
新文字停顿4秒后提交；持续输入没有停顿时，累计等待12秒提交一批，前次请求结束后再处理下一批。
没有新内容时不会重复调用。资料缺少称呼或职责时等待补全；分析失败会暂停自动模式，修复后可重新开启。
“立即分析一次”用于按需立即处理或重试，不是演示中每条发言都要按的按钮。
手动输入框是待提交文字，先点“加入记录”才会进入分析；语音识别的最终结果会自动加入记录。
按钮不可用时，下方提示会说明是会话未开启、未加入发言、资料不完整还是密钥未加载，并给出可执行的下一步。
停止会话、刷新或重开页面后，自动模式需重新开启；不会在用户未操作时自动开始采集或分析。

收集使用反馈
网页顶部“使用反馈”可在操作后或观看演示后填写：
  体验到哪一步、反馈主题、具体发生了什么、希望怎样改。
  对任务的帮助评分和参与编号可留空。
默认只保存主动填写的内容。勾选“附上本次使用情况”才附输入方式、发言/提醒数量等，
不自动附会议原话、回复草稿、姓名、个人背景或API Key。
反馈保存到本目录 data/feedback/，每条独立JSON文件；重置会议和重启服务不会删除它。
一次提交失败会保留输入，相同内容重试复用提交编号，避免因响应丢失而重复保存。
保存成功后再填写的内容属于新反馈；反馈条数不是独立参与人数。
“导出反馈”下载本机所有已保存反馈。异地试用时，请试用者将导出文件交给项目组。
当前没有公共收集网站，也不会自动向项目组或模型服务上传反馈。
data/feedback/已被Git忽略；人工分享代码包时也应按需要排除该目录。
模型对初版的假设走查单独保存在 ../research/assistant_feedback_2026-10-20/，
不自动插入实际界面反馈文件；汇总改进主题时保留各条的收集方式和版本。

真实会议演示前必须验证的两条链路
输入：
    组员真实发言 → 语音转文字 → 已发生的发言列表 → DeepSeek
当前支持手动加入文字、浏览器麦克风转写、实验性的系统音频＋麦克风转写，以及剧本回放。
浏览器转写依赖浏览器、系统语音服务、权限和网络；用户已确认腾讯会议声音能够接收，并有系统混合音频发言进入分析；尚未对照原始音频测量准确率或验证指定应用隔离。
它不是腾讯会议的实时转写API；普通麦克风模式不会自动获取远端组员音频。
本机麦克风来源中的“发言人”是手动设置的标签，不是声纹识别结果。
实验入口在“麦克风”页的“接收腾讯会议中组员的声音（实验）”内：
  “声音来源”默认仍为已能工作的全电脑声音兼容模式，会收录视频、音乐、提示音等其他应用声音。
  要尝试隔离腾讯会议，切换为“指定应用窗口”，在浏览器共享框选腾讯会议窗口，并选“此应用的音频”或同义选项。
  仅选中窗口画面不证明音频已限定。浏览器windowAudio是偏好提示，平台可能忽略；若只有“系统音频”选项请取消，不要确认仅此应用音频。
  取到窗口音轨后须在助手里确认共享框的选择，随后才会开始识别；不支持窗口音频时直接停止，不自动扩大到全电脑声音。
  应用音频可能按进程范围收录同一应用的其他窗口，不等同严格限定某一个会议。指定应用的实际隔离仍需测试。
  “同时收录我的麦克风”可取消；取消后只处理所选共享音频，不请求麦克风权限。记录本人讲话时保留勾选并建议戴耳机，避免扬声器声音再被麦克风拾取。
  模式与麦克风开关在采集中锁定，停止后可切换。以下“整个屏幕”步骤适用于兼容模式：
  使用桌面 Chrome / Edge 135+，点击开始。在浏览器弹出的选择框中选择“整个屏幕”、选中屏幕，开启“同时共享系统音频”，点击共享，再允许麦克风。
  这是浏览器向助手提供声音，不是在腾讯会议中向组员共享屏幕。只选择腾讯会议窗口可能没有音轨。
  页面会显示选屏、等待麦克风、启动识别三个阶段，启动失败时上方状态区同步显示红色原因。
  若提示“没有取得系统音频”，此次共享已自动结束；直接点“重试会议声音转写”，无需再按停止。
  若没有系统音频开关，可换桌面 Chrome 重试或暂用文字输入；取到音轨仍需验证能否识别组员的实际声音。
  建议戴耳机，避免远端声音同时被系统音轨和麦克风重复收录。
  浏览器将系统音频与麦克风混合后交给其语音服务；不自动区分说话人。
  10月22日晚实测发现默认48kHz混音在本机Edge155中未得到有效最终文字；现将混音重采样为16kHz。
  同一中文合成语音在16kHz的两轮隔离测试中均取得最终文字，正式system-audio.js也已实际识别并保存测试文字。一次隔离测试在取得文字后仍报告network，不能据此保证服务始终稳定。
  正常静音结束后会沿用原音轨自动继续识别；30秒内连续结束超过3次时停止并提示。
  network错误最多自动重连2次，取得新的有效最终文字后恢复重试额度；持续失败或权限/音轨错误会停止并提示。手动停止、切换输入方式及停止会话会取消等待中的继续或重连。
  屏幕共享是浏览器取得系统音轨的途径，程序不读取、录制或上传画面。
  音频识别可能由浏览器在线服务完成，并非离线识别，也不是 DeepSeek 的音频接口。
  浏览器版本符合要求仍不保证语音服务可用；未取得系统音轨或服务失败会显示错误。
  选择停止、切换输入页或重置会话会释放共享和麦克风；不会自动重新采集。
  先让远端成员和本机成员各说一句临时新句子，确认两者都出现在发言列表，再正式录制。
正式录制前需要选择：
  A. 已有权限时，使用腾讯会议官方实时转写推送；
  B. 验证实验浏览器转写，或采集本机麦克风和系统音频后接独立ASR；
  C. 只演示文本输入链路，明确说明输入方式。
DeepSeek 在本项目负责文本判断与草稿；填写它的 Key 并不会同时开通语音识别。

输出：
    查看原话 → 编辑回复 → 确认 → 复制 → 本人在腾讯会议聊天区粘贴发送
    → 主持人看到实际消息并回应 → 回助手标记“我已在会议发送”
复制成功只表示复制到剪贴板。“我已发送”是用户自己记录，程序不能核验腾讯会议是否收到。
不会通过模拟键盘悄悄向其他窗口发送消息。
复制后卡片持续显示“已复制，待本人发送或记录”；再编辑草稿会提示当前版本需要重新确认复制。
接收区持续显示当前输入方式、是否采集中、最近一条文字的时间和自动分析开关。
这些状态帮助检查流程，不代表远端声音已经完整收录，也不保证模型没有漏判。
当前提醒显示在页面内，工作时需保持助手窗口可见；后台桌面通知和提示音尚未实现及实测。

使用范围与数据
分析请求只发送当前个人资料、已经输入的发言及近期提醒状态到所配置的官方 DeepSeek 接口。
不发送未来回放台词、其他角色私有背景或主持提示。
所有源文本与模型文字都作为数据展示，不执行其中的指令，不执行模型工具调用。
状态保存在服务进程内存中；刷新网页仍在，重启服务会清空。需要保存时先导出本次记录。
导出区分人工输入、浏览器麦克风、混合会议音频和剧本回放，并记录确认/复制/自报发送等操作。
导出记录不是用户效果研究结论，内容正确性尚未自动评价。
角色变化时会丢弃尚未完成的旧分析。发言过多时按批次处理，不会一次提交无限内容。
角色或背景修改后，旧的未发送建议改为只读历史，需重新分析再使用新草稿。
