公开用户经历资料包（2026-10-16）

目的：为部分参与会议项目提供真实公开叙述的来源线索；不把帖子改造成问卷答卷，不声称招募了这些人。

本轮选择并尝试打开13个来源页，纳入8个来源簇中的14条经历片段，排除5页：3页无法读到原文，2页因范围/日期和重复主题未选。搜索命中总数未系统统计；这不是系统综述或概率抽样。来源覆盖Reddit、Hacker News、Workplace Stack Exchange和Stack Overflow实践博客。

cases.json：匿名案例ID、URL、日期精度、短摘录、中文转述、原作者报告的事实、研究者推断、Q1–10映射、限制。
sources.json：搜索词、筛选口径、每个来源及排除原因、同源引用字数核验。

如何使用：
1. 所有案例是未经身份与事实独立核验的公开自述/亲历观察；不能称为经过核实的用户访谈。
2. 条数不等于人数。按threadClusterId合并看待同串影响；PU12和PU13更是同一文章作者。visibleAuthorClusterId仅为可见作者的匿名归组，不代表已验证个人。
3. 只记录公开文本中明确的内容。Q1/Q3的过去四周频次、Q9/Q10的本项目方案偏好一律not_reported，不能补值或计算“用户支持率”。
4. 评论仅显示相对时间时，postedAt=null，另记threadPostedAt，不能将帖子日期冒充评论日期。事件发生日期与发帖日期也不同。
5. 保留既有办法有效的反例：会后摘要足够（PU08）、个人笔记满足个人关切（PU09）、集中安排会议有帮助（PU07）、协作补记够用（PU14）、耳机旁听已有实践（PU11）。不能把这些反例扩大成“所有人都不需要AI”。
6. PU02/PU05/PU14的具体叙述未明确远程方式；PU13是相邻的远程聊天情境。使用时应同时显示remoteContext和sourceLimitations。
7. 不保存用户名、联系信息、人口特征推断或健康诊断；保留可追溯的公开URL和短摘录。非Reddit同页所有案例的英文直接引文合计不超过25词。没有联系发帖人或获取私有资料。

适合课堂表述：我们补充收集了14条可追溯的公开经历片段，来自8个来源簇；其中包括已有办法够用的反例。这些材料用于修订研究假设和任务情境，不能替代目标用户试填、访谈与原型试用。


补充：original_questionnaire_evidence_map.json 对照两份原问卷的27+14主问题与7模块，共48项。只列历史材料的部分关联；频率、分数与假设方案偏好保留缺失，没有伪造完整答卷。原cases.json中的Q1–Q10仍指统一短问卷，两者题号不能混用。
